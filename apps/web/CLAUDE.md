# apps/web

- **Call the API through `api` from `@/api/api-client`, never `fetch` directly.** Its base URL is the relative `/api`: in dev Vite proxies it to the API; in production nginx serves both on one origin. An absolute URL like `http://localhost:3000` breaks production and needs CORS.
- **Pass every call the response's schema from `@ratewatch/contracts`** (`api.get('/health', healthResponseSchema)`). The client parses with it and infers the type from it; never cast with `as` or add a result type. The API is a trust boundary for the browser too. To read a response header, pass its schema too (`{ responseHeaders: rateLimitHeadersSchema }`) and use the returned `responseHeaders`; never read raw `Headers`.
- **Pages are thin; features mirror the UI** (ADR-0011). A page in `pages/` only lays out features. Everything only one feature uses lives in `features/<feature>/`: a component with parts gets a folder named after it with its main file inside (`users-table/users-table.tsx`); two or more parts with one role share a role folder (`cells/`, `states/`, `controls/`), at most one such level per component folder; a single part sits beside its main file; `hooks/`, `utils/`, `types/` only at the feature root. No `index.ts` barrels. Follow `features/users/` as the example.
- **Shared folders hold what two or more features use**: `components/`, `api/` (`api-client.ts`, `api-error.ts`, then `api/<resource>/` with `<resource>-queries.ts` and its one-line hooks; for a new resource copy `api/health/` plus `mocks/data/health.ts` and `mocks/handlers/health.ts`), `theme/`, `utils/`, `mocks/`, `test/`. API hooks stay in `api/` even when one feature uses them. When a second feature needs a feature's code, move it to a shared folder. Lint stops shared folders importing a feature or page, features importing each other or a page, and pages importing each other. Create a folder with its first real file, never a `.gitkeep`.
- **Import across folders with `@/`** (the `src/` root), not long `../` chains. Inside a feature, import its own files relatively.
- **Server state is TanStack Query** (ADR-0012). Branch on errors with `instanceof ApiError` / `RateLimitedError` from `@/api/api-error`, never by parsing messages.
- **No `useEffect`.** Lint bans it; follow the `no-use-effect` skill. The one exception is a component's own timer or subscription: disable the rule on that line with a `--` reason.
- **Desktop only.** Design and test for desktop browser windows 1280px and wider; don't add phone or tablet layouts or responsive breakpoints.
- **Pages go in `pages/`, URLs in `ROUTES`** (ADR-0014): add the URL to `app/route-paths.ts`, then the route to `app/routes.tsx`. Never write a path string in a link or route.
- **Never hardcode a colour** (lint fails on hex, `rgb()`, `hsl()` outside `theme/`). Use theme tokens; add a missing one to `DESIGN.md` and `theme/palette.ts` first. Fixed sizes come from `theme/sizes.ts`.
- **Customise MUI components in the theme**, one file per component in `theme/components/` (overrides and custom variants such as `<Button variant="shellTab">`), not with `sx` copied between call sites.
- **Every component has its spec beside it; a page's spec only covers wiring.** Render one component with `renderWithProviders(<Component />)` from `@/test/render-app` (real providers, MSW answering); a props-only component gets props and `vi.fn()` callbacks. Use `renderApp(url)` only in a page's spec. A test that crosses components goes in their nearest common parent's spec. Assert what the user sees; simulate errors with `server.use(...)`; never mock hooks, the client or query keys. Pure logic with many cases (`clicker-view.ts`) gets plain unit tests beside it.
- **Write functions and components as `const` arrow functions**, never `function` declarations.
